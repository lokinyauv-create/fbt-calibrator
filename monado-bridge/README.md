# Monado bridge / Міст для Monado

Generated by AI (Claude, Anthropic) for [Lokinya](https://github.com/lokinyauv-create). BSL-1.0 (same as Monado).

Monado cannot load SteamVR drivers, so the calibration is done where Lighthouse poses enter Monado:
its `steamvr_lh` driver. `fbtcal.hpp` goes into `src/xrt/drivers/steamvr_lh/` and is hooked into
`Device::update_pose()` in `device.cpp`:

```cpp
#include "fbtcal.hpp"
// at the top of Device::update_pose(), after `valid` is known:
uint32_t fbt_kind = fbtcal::OTHER;
switch (device_type) {
case XRT_DEVICE_TYPE_HMD: fbt_kind = fbtcal::HMD; break;
case XRT_DEVICE_TYPE_LEFT_HAND_CONTROLLER: fbt_kind = fbtcal::LEFT; break;
case XRT_DEVICE_TYPE_RIGHT_HAND_CONTROLLER: fbt_kind = fbtcal::RIGHT; break;
default: break;
}
const bool fbt_is_tracker = name == XRT_DEVICE_VIVE_TRACKER;
if (fbt_is_tracker) fbt_kind = fbtcal::TRACKER;

// where the pose is invalid (before sync_dark_pose()):
xrt_pose none = XRT_POSE_IDENTITY;
fbtcal::Bridge::get().publish(serial, fbt_kind, false, none, none);

// after the chaperone transform, before the pose goes into the relation history:
const xrt_pose fbt_real = relation.pose;
if (fbt_is_tracker &&
    fbtcal::Bridge::get().apply(serial, relation.pose, &relation.linear_velocity, &relation.angular_velocity) ==
        fbtcal::OVERRIDE) {
	relation.linear_velocity = {};
	relation.angular_velocity = {};
}
fbtcal::Bridge::get().publish(serial, fbt_kind, true, fbt_real, relation.pose);
```

It publishes every device's real and final pose to `/dev/shm/fbtcal-devices-v2` and applies what the app
writes to `/dev/shm/fbtcal-v1` (offsets, the VRChat freeze, and for the waist the sitting fix).
Tested on a Monado 25.1 fork (`steamvr_lh` with controller hot-plug), Valve Index + VIVE Tracker 3.0.

Monado не вміє завантажувати драйвери SteamVR, тому калібрування робиться там, де пози Lighthouse
потрапляють у Monado: у драйвері `steamvr_lh`. Як підключити — код вище.
